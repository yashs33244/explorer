Problem.

  • Who: customers paying through the shop app.
  • What they see: Receipts tab empty, "No receipts yet".
  • Seen: 2026-01-12, account acct_9 (illustrative).
  • Why: the tab reads events; charges write only the receipts table.
  • A receipt is one row in payments.receipts.
  • The worker writes it after the API queues a job.
  • The Receipts tab never reads that table.
  • Fix: read the receipts table when there are no events.

01

What was reported

Support ticket, 2026-01-12: "I paid for my order and got the email, but my Receipts page is empty."

Problem in one line

The tab only counts events, so paid charges are recorded but never shown.

Solution in one line

When there are no events, the tab reads the receipts table directly.

Not the cause

A failed payment. The charge returned 201 paid and the row exists.

02

What a receipt is, from first principles

  • A paid charge must be provable later.
  • So each charge needs one durable record: who, how much, when.
  • That record is a receipt.
