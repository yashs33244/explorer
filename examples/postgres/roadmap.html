1. Build it and get a green baseline

Install meson, ninja, bison, flex and icu with brew. From repos/postgres:

meson setup build --buildtype=debug -Dcassert=true -Dtap_tests=enabled
ninja -C build
meson test -C build --suite setup --suite regress

Turn on cassert while developing. Leave it off when you benchmark.

2. Ask the code graph

graphify already mapped the source into repos/postgres/graphify-out/graph.json (about 47,000 nodes). Ask it questions from repos/postgres:

graphify query "how does a commit reach the WAL?"
graphify explain "heap_insert"
graphify path "PostgresMain" "XLogInsert"

Read GRAPH_REPORT.md next to it for the main communities.

3. Watch a query move through the code

Start a server, connect with psql, attach lldb to the backend process and break at exec_simple_query. Step into raw_parser, then pg_plan_queries, then ExecutorRun.

4. Look at the real container

Docker was not running when I wrote this, so these commands are untested. Start Docker Desktop, then:

docker run -d --name pg -e POSTGRES_PASSWORD=x postgres
docker exec pg sh -c 'echo $PGDATA; ls -la $PGDATA; id'
docker exec pg sh -c 'ps -eo pid,user,args | head'
docker exec pg df -h /dev/shm
docker stop pg   # watch the logs: SIGINT, fast shutdown

Match what you see with the Docker and files-on-disk parts above.

5. Look at real pages

Create the extensions pageinspect, pg_buffercache and pg_visibility. Insert, update and delete a row, then read the raw page with heap_page_items to see xmin, xmax and line pointers change.

6. Review before you write

Subscribe to pgsql-hackers. Pick a small patch in the Commitfest app, apply it, run the tests and reply with what you found. This is the fastest way to learn the style and get known.

7. Pick a small first patch and send it
  • A docs fix, a clearer error message or a missing test.
  • Make the patch with git format-patch, one version per revision (v1, v2, ...).
  • Email it to pgsql-hackers with a short cover note: what, why, how you tested.
  • Register it in the Commitfest app. Run pgindent on the files you changed.
Before you send anything: check the AI rules

PostgreSQL contributors are still discussing how AI-assisted patches should be handled. Read the current policy and recent pgsql-hackers threads first. Write and understand every line yourself, because reviewers will ask you to explain it.
